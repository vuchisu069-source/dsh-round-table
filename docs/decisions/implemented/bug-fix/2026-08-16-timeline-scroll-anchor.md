# 2026-08-16 — 时间线滚动位置保护（scrollTop 精确恢复）

**分类**：bug-fix
**状态**：implemented

## 现象

圆桌面板时间线滚动后跳动：滚到顶部/中间阅读历史，数秒内被拽走；骨架总结区（右栏）
滚动同样复位。

## 根因（两阶段）

1. `renderTimeline()` 每次渲染末尾强制 `scrollTop = scrollHeight`。client 每 3 秒轮询
   `/state`（SSE 断线兜底），每次状态往返都重渲染 → 阅读位置被拽回底部。
2. 第一版修复用「锚定首个可见项 + `scrollIntoView({block:'start'})`」——但
   `scrollIntoView` 会把锚点**强制钉到视口顶部**：阅读中间位置时，内容会整体上跳
   一个视口高度，表现为"莫名其妙跳动"。右栏总结卡另有 `max-height` 内部滚动，
   重建时内部滚动位置丢失。

## 修复（最终）

- **三栏统一**：重渲染前记录 `scrollTop`，重建后直接恢复 `scrollTop = prevTop`。
  消息只追加在底部、视口上方内容高度不变 → 精确恢复即保持阅读位置，零跳动。
- **贴底跟随**：距底 <48px 且 `scrollHeight` 确实增长时才滚到新底部。
- **总结卡**：去掉 `max-height`/内部滚动，并入右栏整体滚动（受同一保护）。

## 验证

无头 Chrome：中间位置 scrollTop=522 → 30s（含新消息到达）偏差恒为 0；
顶部位置保持；右栏总结区滚到底部后跨轮询周期保持。贴底态新消息仍自动可见。
