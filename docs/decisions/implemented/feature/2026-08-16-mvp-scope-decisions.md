# 2026-08-16 — MVP 范围五项决策

**分类**：feature
**状态**：implemented（已拍板，进入实现）

## 背景

round-table（圆桌）插件设计评审阶段提出的 5 个开放问题，由用户拍板确定，作为 MVP 实现基线。

## 决策

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| D1 | 成员模型选择 | **统一模型**：所有 Agent 成员沿用主会话 provider/model；v2 再放开单独配置 | 成本可控、实现简单；多模型是体验增强而非核心价值 |
| D2 | 页面离开行为 | **默认暂停**，可配置为后台继续 | 防意外产生费用；讨论是用户在场时的协作活动 |
| D3 | 总结产出形式 | **纯文本卡片**；结构化（结论/分歧/行动项）留待 v2 | 快速可用；结构化依赖讨论数据质量，晚点做更稳 |
| D4 | 插件名 | `round-table`（圆桌） | 贴合"研讨房间 + 主持人 + 圆桌讨论"隐喻 |
| D5 | 角色来源 | **用户自己创建与命名**（无内置模板库）；角色库跨房间复用 | 避免官方固化角色人格；用户自定义才贴合各自领域 |

## 影响

- 实现时不引入"按成员选择模型"的配置面（D1）
- client 需监听页面可见性并在离开时调用控制接口暂停（D2）
- 总结者输出为纯文本，不做结构化 schema（D3）
- 仓库名/包名/标题用 round-table（D4）
- 状态模型含"角色库"（role library）概念：角色与房间成员解耦（D5）
